# Contributing

Thank you for your interest in contributing to this project.
This is a friendly contribution, the bellow explanations are just for the cleanest contribution version, there's no obligation for following the exact instruction, just enjoy coding and do your best. Thanks.

## Reporting Issues

Before opening a new issue, please first check whether it has already been reported.

When reporting a bug:
- Clear description of the problem.
- Steps to reproduce it.
- Expected behavior as it wants in the template.
- Actual behavior according to what template wants.
- Environment details if necessary to run the project and see the problem.

## Pull Requests

Before submitting a PR (Pull Request):
- Fork the repository.
- Create a new branch for your changes and task.
- Keep commits focused and meaningful.
- Follow the existing project structure and coding style for consistensy.
- Ensure your changes don't break existing functionality.

When your work is ready, open a pull request and provide a clear description of the changes.

## Code Style

Please follow the existing conventions used throughout the project. Consistensy is preferred over personal style. The **Code Style** and its structure is not really a special thing, just follow the **PEP-8**.

## Discussions

For feature ideas or architectural changes, open an issue before starting implementation. This helps avoid duplicated work/task and ensures the proposal aligns with the project's direction.
